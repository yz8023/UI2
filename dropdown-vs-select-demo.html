这条视频到底讲了什么

按视频的叙述顺序还原：先抛出「两个几乎一样的东西为什么要分开」，再用一句官方定义定性，最后用三条铁律收尾。下方所有演示都可以在「对比演示 / 三条铁律」里真点。

1开场：一个真问题

A
屏幕上是两个视觉几乎完全相同的「下拉」：都有一个小箭头，点开都是一列选项。
B
但打开大厂组件库（Arco、Ant Design 等），它们被拆成两个独立组件，连文档都分开写。
C
原因不是「长得不一样」，而是职责不一样：一个负责「选一个值」，一个负责「执行一堆命令」。

2一句话判定

视频直接引用 Arco Design 的官方描述：
Select is for selection（选择器是用来「选」的）
Dropdown is a collection of commands（下拉菜单是一堆命令的集合）。
记住这一句，后面所有判断都是它的推论。

3拆解 Dropdown 下拉菜单

  • 属于导航与操作，不是表单控件。
  • 触发器通常是没有外边框的文字按钮、图标按钮或头像。
  • 点菜单项 = 立刻执行：跳转、复制、分享、删除……
  • 没有「当前值」这个概念，不需要回显、不需要提交。
  • 典型：导航栏菜单、表格行尾的「更多操作」、导出 / 分享入口。

4拆解 Select 选择器

  • 属于数据录入，天生是表单里的一个字段。
  • 必须有一个带外层边框的输入框，里面有占位符或当前值。
  • 选中后值回填进框里，还要支持清除、禁用项、校验。
  • 它只负责「记录」，真正生效要等表单提交。
  • 典型：选城市、选部门、选状态、多选标签。

5叫错名字的真实代价

  • 设计稿做错形态：给菜单套上输入框边框 → 用户以为要「填表」，结果一点就跳走了。
  • 开发用错组件：Dropdown 的模型是「命令」，Select 是「值 + 校验 + 提交」，混用要多写一堆胶水代码。
  • 跟 AI 说不清：一句「做个下拉框」，AI 大概率给你一个四不像——带边框的菜单，或者没有回显的表单。
  • 无障碍跑偏：两者的 role、焦点管理、读屏播报完全不是一套东西。

6三秒自查：问自己三个问题

  • 选完要不要提交 / 生效？要 → Select
  • 点一下是不是立刻就发生了一件事？是 → Dropdown
  • 外面有没有一个框正在装着当前值？有 → Select
  • 选项是不同动作（编辑 / 删除 / 分享）还是同一维度的数据（北京 / 上海 / 深圳）？前者 Dropdown，后者 Select。
